flint-chart 是什麼？

一個語意化圖表編譯器。

你只寫一份與後端無關的規格：
chart_spec（圖種＋欄位對應＋標題）＋ semantic_types（欄位語意型別）

它編譯成 Vega-Lite / ECharts / Chart.js 三種前端可渲染規格。

顏色、字級、座標軸刻度、後端 JSON —— 你都不寫，由語意推導。

輸入範例

你只寫這個

  • chartType："Bar Chart"
  • encodings：x → product_line、y → revenue、column → region
  • semantic_types：revenue: "Amount"、region: "Region"

revenue 標成 Amount → 自動貨幣格式、自動零基準、自動排序方向。

語意型別是護欄：告訴它「這是價格 / 排名 / 相關係數」，格式與配色就對了。

誰需要它

前端／全端工程師

痛：三大圖表庫 API 心智模型完全不同，換庫＝重寫。

解：一份規格 → 三種後端，品牌樣式集中在一個 theme_spec。

資料工程師

痛：繪圖邏輯寫死在 notebook，不能 diff、不能重放。

解：圖表規格是純文字 artifact，可版控、可回溯。

AI Agent 開發者

痛：讓 LLM 硬吐後端 JSON，常壞、難驗證、換後端要改 prompt。

解：窄生成目標＋validate_chart 內建驗證＋MCP 原生。

核心觀念

同一個問題，三種角色

flint-chart 用「語意規格 → 編譯 → 多後端」的結構，同時解掉三種角色的同一個問題：
讓「意圖」與「實作」解耦。
這正是 AI to Agent 主張的分層：人（或 Agent）只表達語意，工具層負責可替換的實作。
AI to Agent 閉環

Flint 在整個閉環的位置

              KNOW-HOW  （企業 Know-how）
                 │
                 ▼
                VAD   讓需求 / 資料 / 流程被看見
                 │
                 ▼
                VAC   能力規格・工具規則・驗收標準
                 │
                 ▼
            ORCHESTRATOR   依任務分派
                 │
      ┌──────────┼──────────┐
      ▼          ▼          ▼
   UI Agent  Data Agent  Process Agent
      │          │          │
    Figma   Flint Chart   Mermaid
      └──────────┼──────────┘
                 ▼
              VERIFY   結果是否符合規格？
                 │
                 ▼
               REUSE   成功能力持續重用
                 │
                 ▼
              KNOW-HOW ──↺  （回寫，循環）

VAD／VAC 把 Know-how 轉成規格 → Orchestrator 分派 → Data Agent 綁 Flint Chart → Verify 驗收 → Reuse 回寫。上層工具（Figma／Flint／Mermaid）可換，閉環不動。

意圖層 vs. 被甩掉的實作層

角色他要的「意圖層」flint 幫他甩掉的「實作層」
前端工程師「一張帶分面、依值排序的長條圖」三種圖表庫的 API 差異
資料工程師「pipeline 末端要這張圖，且能重放」寫死在 notebook 的繪圖碼
Agent 開發者「把這張表變成對的圖」讓 LLM 硬吐易壞的後端 JSON
給 Agent 開發者

好的 Agent 工具長什麼樣

好工具 ＝ 窄輸入介面 ＋ 語意護欄 ＋ 內建驗證 ＋ 後端可換
  • 窄輸入：Agent 只需產 chart_spec + semantic_types，欄位用名稱引用
  • 語意護欄：型別驅動格式與配色，Agent 不亂調顏色軸刻度
  • 內建驗證：validate_chart / create_chart_view 先替它檢查
  • 後端可換：換 Vega-Lite / ECharts / Chart.js 不用重寫 prompt
現場動手

兩分鐘示範

  • 掛上 MCP：npx -y flint-chart-mcp
  • 給一段表格資料，請 Agent 產 ChartAssemblyInput
  • create_chart_view → 互動圖，當場改主題（nyt / economist / mckinsey…）
  • compile_chart → 印出 Vega-Lite JSON，對照「你沒寫的東西」

重點提問：如果今天不用 flint，Agent 要多寫多少、錯多少？
